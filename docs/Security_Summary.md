# 安全总结 - Azure AD 集成

## 概述

此次集成为 RuoYi.Net 添加了 Microsoft Azure Active Directory (AAD) 单点登录功能。以下是安全方面的考虑和建议。

## 实施的安全措施

### 1. 依赖包安全

- **Microsoft.Identity.Web**: 使用最新稳定版本 4.3.0，无已知安全漏洞
- **Microsoft.Identity.Web.UI**: 使用版本 4.3.0，无已知安全漏洞
- 所有依赖包通过 `gh-advisory-database` 工具验证

### 2. 认证流程安全

- 使用 OAuth 2.0 授权码流程 (`ResponseType = "code"`)
- 通过 OpenID Connect 标准协议进行认证
- 令牌安全存储在服务器端 (`SaveTokens = true`)

### 3. 配置安全

- 客户端密码 (`ClientSecret`) 存储在配置文件中
- **建议**: 生产环境应使用环境变量或 Azure Key Vault 存储敏感信息
- 配置包含启用/禁用开关，默认为禁用状态

### 4. 用户管理安全

- **不自动创建用户**: AAD 登录不会自动在系统中创建用户账号
- 必须预先在系统中创建用户，防止未授权访问
- 用户状态检查：验证用户是否被删除或停用

### 5. 日志记录

- 记录所有 AAD 登录尝试（成功和失败）
- 登录日志包含用户名、状态和消息
- 便于安全审计和异常检测

### 6. 权限控制

- AAD 登录用户遵循系统现有的角色和权限设置
- 不会因为使用 AAD 登录而获得额外权限
- 保持与传统登录方式相同的权限模型

## 安全建议

### 1. 保护客户端密码

**高优先级**

```bash
# 使用环境变量
export AZURE_AD_CLIENT_SECRET="your-secret-here"

# 在 appsettings.json 中引用
{
  "AzureAd": {
    "ClientSecret": "${AZURE_AD_CLIENT_SECRET}"
  }
}
```

**建议使用**: Azure Key Vault、Kubernetes Secrets、环境变量

**避免**: 将密码提交到版本控制系统

### 2. HTTPS 要求

**强制要求**

- 生产环境必须使用 HTTPS
- 确保回调 URL 使用 HTTPS 协议
- 配置 HSTS (HTTP Strict Transport Security)

### 3. 定期密码轮换

**建议**: 每 90 天轮换一次客户端密码

步骤：
1. 在 Azure Portal 创建新的客户端密码
2. 更新应用配置
3. 测试新密码
4. 删除旧密码

### 4. 最小权限原则

在 Azure Portal 中：
- 只授予必要的 API 权限
- 当前配置只需要 `User.Read` (Delegated)
- 避免授予过多权限

### 5. 监控和审计

**建议配置**:
- 启用 Azure AD 登录日志
- 定期检查系统登录日志
- 设置异常登录告警

### 6. 租户配置

**建议**:
- 在 Azure AD 中启用条件访问策略
- 配置多因素认证 (MFA)
- 限制允许登录的 IP 地址范围

## 已知限制

### 1. 用户管理

- AAD 登录不会自动同步用户信息
- 用户属性更新需要手动处理
- 需要管理员预先创建用户账号

### 2. 单点登出

当前实现不包括单点登出 (Single Sign-Out) 功能
- AAD 登出不会自动登出应用
- 应用登出不会登出 AAD 会话

**改进建议**: 实现完整的 OpenID Connect 登出流程

### 3. 令牌刷新

当前实现不包括令牌刷新机制
- JWT 令牌过期后需要重新登录
- AAD access token 不会自动刷新

## 应急响应

### 如果客户端密码泄露

1. **立即行动**:
   - 在 Azure Portal 删除泄露的密码
   - 创建新的客户端密码
   - 更新应用配置
   - 重启应用

2. **审计**:
   - 检查 Azure AD 登录日志
   - 查看应用登录日志
   - 确认是否有未授权访问

3. **通知**:
   - 通知安全团队
   - 通知相关用户

### 如果检测到异常登录

1. 确认是否为真实用户行为
2. 如果不是，立即停用相关用户账号
3. 审查登录日志
4. 检查是否有数据泄露
5. 必要时重置用户密码

## 合规性

### GDPR 合规

- 用户数据处理遵循 Microsoft 隐私政策
- 登录日志包含个人信息（IP 地址、用户名）
- 建议实施数据保留策略

### SOC 2 考虑

- 启用审计日志
- 实施访问控制
- 定期安全审查
